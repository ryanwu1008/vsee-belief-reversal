# VSee Source Registry and XTrace Memory Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a public source registry with exact MongoDB lineage and a safe, deterministic path for importing authorized legacy XTrace/Supabase data.

**Architecture:** Enrich each bounded `context_units` document with source provenance, project every active source into the demo snapshot, and merge retrieval selection metadata without changing decision semantics. Keep live private-data access out of the public importer and let Atlas generate new embeddings.

**Tech Stack:** TypeScript, React, Node test runner, MongoDB Atlas, Atlas Automated Embedding, Atlas Vector Search, Fireworks AI, Vinext/Sites.

**Spec:** `docs/superpowers/specs/2026-08-13-vsee-source-memory-migration-design.md`

## Global Constraints

- Private pitch decks, internal decisions, and company memories never appear on the public site.
- Only HTTP(S) canonical URLs may render as clickable external links.
- Public reference sources cannot substantiate synthetic Irregular metrics.
- Existing PASS/REVISIT behavior and Fireworks decision guardrails remain unchanged.
- Production changes follow RED, GREEN, REFACTOR and include fresh verification.
